# 既知の制限

「仕様上の上限」と「判定が曖昧になるところ」をまとめます。直す予定のあるものではなく、現状の挙動の記録です。

## 入力の解釈（高速モード）
- `/` は曲名と P 名の区切りとして扱う。`AC/DC` のように曲名に `/` を含むと `AC` と `DC` に分かれる（`／` も同じ）。
- 引用符なしのカンマは列の区切りとして扱う。英語タイトル `Hello, World` は曲名 `Hello`・P名 `World` になる（`"Hello, World"` と引用符で囲めば1つの曲名）。
- `A - B` は、チャンネル名が分かる動画では一致する側を P 名、分からないときは左を P 名・右を曲名とみなす。逆の並びの資料は誤判定しうる（AI 抽出モードを使う）。
- 曲名の候補が 400 文字を超える行と、2000 文字を超える行は曲として扱わない（段落や巨大な1行で処理が止まらないようにするため）。
- 曲名が 120 文字を超える行は曲として扱わない。
- 順位だけの行（`100位` `No.1`）や、3文字以上の区切り線（`=====` `-----` `━━━` `***`）は曲として扱わない。数字だけの曲名（`100`）や `!!!` のような記号だけの曲名は残る。
- 演奏済みリスト・セトリの重複警告は、記号だけの曲名（`!!!` など）を照合しない（抽出結果の重複排除は記号だけの曲名も扱う）。

## 上限
| 項目 | 上限 |
|---|---|
| URL | 30 件 |
| テキスト | 30 万文字（超えた分は切り捨て） |
| ファイル | 10 個・合計 4MB。PDF・画像は AI キーが必要 |
| Web ページ | HTML のみ（JavaScript で描画するページは本文が取れない）。受信 2MB・本文 6 万文字まで |
| プレイリスト | API キーあり 300 曲 / なし 約 100 曲 |
| 動画情報 | 500 件まで。API キーなしは 50 件まで |
| 動画 URL の自動検索 | URL のない曲の先頭 40 曲まで（統計モードは API で 20 曲まで）。残りは「YouTube検索」リンクで確認 |
| AI に渡す資料 | 20 万文字まで |
| 抽出リクエスト | 1 分に 12 回（IP またはアカウントごと）。サーバーのインスタンスごとの簡易制限 |
| タブ / 履歴 / セトリ | 10 個 / 最新 20 件 / 50 件（1 セトリ 300 項目まで） |

## 保存
- ブラウザの保存領域（localStorage）は約 5MB。履歴は約 150 万文字までに自動で減らす（古いものから削除。1 件だけで大きすぎる結果は履歴に残らない）。プリセットのテキスト（1 タブ 30 万文字まで）と合わせて容量を超えると、新しい保存が失敗することがある。
- 保存はその端末のブラウザだけ。別の端末・別のブラウザとは自動では同期されない（バックアップで移す）。

## 性能
- 数百曲までは快適に操作できる（500 曲で、入力・選択がおおむね 0.1 秒以内）。数千曲になると一覧の DOM が増えて重くなる（一覧の仮想化はしていない）。数千曲を扱う場合は、検索・絞り込みで表示を減らす。
- 印刷用の表は画面に出さないが、結果と同じ件数だけ作られる。

## 外部サービス
- YouTube・SoundCloud の取得、AI（Gemini・OpenAI）、Excel 読み込みの `xlsx` は外部に依存する。無料枠の超過・仕様変更・遮断で失敗することがある（失敗は警告やエラーで表示し、他の機能は動く）。
- AI の出力は不正確なことがある。BPM・Key は AI が確実なときだけ返す設計（空欄になることが多い）。MMD の有無は AI の知識による判定。
- Key の判定は C〜B・♯♭・Camelot（`8A` など）・`major/minor` 表記に対応。ドイツ式の `H` 表記は未対応。

## 音声入力
- ブラウザ標準の音声認識を使う。対応状況は端末・ブラウザに依存し、HTTPS とマイクの許可が必要。ブラウザによって音声がその提供元の認識サービスに送られる。オフラインでは使えない。
- 1つの文章で列挙した曲名の自動分割はしない（1 曲ずつ話すか、停止後に改行で区切る）。

## ログイン
- Vercel のプレビュー URL ではログインできない（Google にリダイレクト URI を登録できないため）。
- ログイン有効時は、Google でメールアドレス確認済みのアカウントだけを受け付ける。
